# 鲸鱼伴游设计 · 参考站点分析

检查日期：2026-10-04。参考：[Vikash Singh 的主页](https://vikash-singh.me/)。

## 本次已修正的定位问题

上一版只有视口宽度至少 1360 px 才使用固定定位。更窄的窗口，包括 Codex 的内嵌浏览器，会把宠物放到主页内容末尾。它虽然有眨眼和喷水，但世界坐标不变，视觉上仍像一个带动画的小控件。

现在所有宽度都使用视口固定定位。1280 px 以上停在左侧留白的中下部，底部间距约为视口高度的 24%；窄屏采用左下方的小尺寸停靠。保留桌面 132 px、窄屏 108 px 的图片盒子，提示文字按悬停/键盘焦点显示。窄屏缺少侧边留白，悬浮角色仍会覆盖局部正文，可以通过关闭按钮收起；这一定位修正尚不包含自由游动或自动避让。

## 参考站点实际采用的实现

已在浏览器确认：页面有 Lemma（狗）和 Mochi（猫），桌面 WebGL 环境默认启用 3D。点击宠物面板的 play 后，小狗追向抛出的球；本次观察到其水平位置由约 893 px 移动到约 1259 px。3d 按钮可切换到 SVG 外观。

公开代码可见的结构：

- **视口覆盖层**：`.cmp-layer` 使用 `position: fixed` 覆盖视口，整体 `pointer-events: none`；宠物和操作面板才接收点击。滚动页面时，角色仍在视口内。
- **独立的行为数据**：每只动物记录当前位置、目标位置、速度、朝向、姿态、眨眼、情绪、精力、饱腹度。
- **运动更新**：`requestAnimationFrame` 驱动行为与位置更新，包含漫步、追球、叼回、进食、被拖起、落地及双方互动等状态。地面基准是视口高度减去宠物尺寸与底部留白，所以它们主要在屏幕下沿活动。
- **两套外观**：2D 使用分层 SVG、CSS 关键帧和 DOM 变换；3D 动态加载 Three.js（包内标识 revision 185）。3D 模块用透明 WebGL 渲染器、正交相机、灯光，以及球体/胶囊等几何体组合猫狗模型，根据同一套行为数据调整腿、头、尾巴和身体。
- **交互与连续性**：代码包含抚摸、拖动、喂食、玩具、动作指令、情绪指标、本地存储；同时处理隐藏标签页与减少动态效果。

这些证据支持“代码驱动的宠物行为系统 + 可切换渲染层”的判断。没有证据表明它由 Figma 自动导出或使用 Live2D / Rive。页面的鱼图标在这里是猫的食物道具。

## 我们应该借鉴什么

当前鲸鱼的立体感来自固定视角的原图材质，SVG 负责裁剪和分层。这足够支持高质量的二维游动；想实现真正的转身、侧后方和随光照变化的高光，需要建立三维模型。外观渲染和行为设计可以分开迭代。

参考站点让人觉得有趣的核心包括：有目标的移动、动作前后的停顿、不同状态的动作节奏、对用户输入的反馈，以及不操作时自己的小习惯。我们的下一阶段应优先补齐这些行为。

## 推荐的三个活动区域

| 方案     | 默认位置与路径                             | 适合程度                                 |
| -------- | ------------------------------------------ | ---------------------------------------- |
| 侧边伴游 | 宽屏左侧留白、中下部；沿侧边短距离上下巡游 | 推荐作为阅读时的默认模式                 |
| 底边游弋 | 视口底部上方的小范围横向移动               | 适合窄屏停靠、休息，以及需要更安静的页面 |
| 自由探索 | 主动进入玩耍模式后，沿大弧线探索页面       | 适合短暂互动；结束后回到侧边             |

正文、链接、导航、返回顶部按钮和打开的弹层应作为避让区域。左侧没有足够留白时回到角落，而不是强行压在文章上。拖动结束后把宠物限制在可见范围，并提供键盘可用的“回到侧边 / 休息”操作。

## 推荐动作脚本

1. **阅读伴游**：大部分时间安静悬浮。每隔约 20–40 秒，沿留白移动 100–180 px，用 3–6 秒到达；到达前减速，停下后看看鼠标或眨眼。具体频率需结合阅读体验调低。
2. **游泳节奏**：头部先朝移动方向微倾，身体随后移动，尾巴稍有延迟；速度改变时同步改变摆尾频率。小鲸鱼使用缓慢、上下起伏的节奏。
3. **喷水**：用户点击后先上浮约 15–25 px，停顿 100–150 ms，喷水并散开水滴，随后轻轻回落。游动时只留下少量短暂气泡；连续点击合并反馈，避免水滴累积。
4. **阅读状态**：滚动或选择文字时停止大范围移动，靠边安静陪读。文章/论文页可使用现有 Reading 图层；它是语境反馈，不宣称识别用户正在阅读的具体句子。
5. **玩耍**：点击“玩一会儿”后出现可追逐的气泡。鲸鱼转向并游过去，气泡破裂后开心；交互结束或用户继续滚动时回到侧边。
6. **休息**：睡眠停止喷水，缓慢呼吸；关闭、减少动态效果或标签页隐藏时停止不必要的运动。

“海洋感”可以由缓慢的浮力、弧线运动、偶尔的气泡与短暂水纹表达。保留主页的大面积清爽留白，喷水和水纹只在互动时出现。

## 实现路线

**下一版继续使用 Astro + 当前分层 SVG + TypeScript。** 增加目标坐标、速度、转向、避让和拖动。移动状态（停靠 / 游动 / 拖动）与表情状态（待机 / 开心 / 阅读 / 睡眠）分开管理。只在移动或物理反馈发生时持续更新位置；到达目标后回到轻量的待机动画。

如果确实需要像参考站点一样转身、翻滚和真实透视，再通过 Blender 建立保留原轮廓的轻量鲸鱼模型，使用 Three.js 加载 GLB。Figma 继续负责图形与界面；Rive 可用于二维形变，但不负责真实三维光照。当前项目没有加入 Three.js、3D 模型或自由游动系统。

本次会话中的三种动态位置示意用于比较设计方向，采用已有鲸鱼图像，尚未把其中的游动路线接入生产组件。
